A Task Progress List guides users through a complex workflow by breaking it down into a clear set of related tasks, each with its own action and completion status.

## Guidance

### When to use the component

- **Complex workflows:** Use this for complex workflows that involve completing multiple tasks.
- **Non-sequential workflows:** Tasks that can be completed independently and in any order. We call them "Tasks" instead of "Steps" because "step" implies a strict order.
- **Multiple sessions:** Use this for processes that may take someone multiple visits to the website to finish.
- **Task tracking:** Use this when you need to show the status for each task, such as “In progress” or “Completed”.
- **Ideal number of tasks:** This component works best for workflows with 3-6 tasks.

### When to consider something else

- **Single-page forms:** Do not use this to replace a single-page form.
- **Simple workflows:** Do not use this for workflows where all steps must be completed in order.
- **Destructive actions:** If an action would delete information someone has entered (e.g. use a confirmation modal instead).
- **Reviewing before submit:** This component is not designed to display all entered information at once for review, before submit. If you need to review entered information before submitting it, that should happen on a separate page.

### Key Characteristics & Behavior

- **Complete in any order:** Someone can complete the tasks in any order they choose (unless a task is blocked by a prerequisite one).
- **Clear status over position:** To prevent disorientation, tasks should always be displayed in the same order. The status labels show which steps are completed or not.
- **Review step:** The last task in the list will often be a "Review and submit" task. Keeping this review step inside the main task list is a reminder to finish the overall workflow (e.g., completing a registration or filing a claim).
- **Informational content:** You can optionally include some contextual details (saved data) within the task steps. This is helpful if someone leaves and returns after a long time, without needing to go into each step.
  - For completed tasks, you may choose to show a short summary of saved data. Consider what minimum context is needed for someone to remember what they filled out in that task.
  - For in progress or not started tasks, an alert can be added to emphasize those.

## Task Statuses

Set the status of each task using the status parameter:

| Status  | Default Label    | Description                                                                                                                                                                                                     |
| ------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| todo    | Not started      | The task has not been started.                                                                                                                                                                                  |
| doing   | In progress      | The task has saved data, but is not finished. This commonly occurs when a user starts a task, saves data, and then leaves.  Not all tasks have In Progress. Some go straight from "Not started" to "Completed". |
| done    | Completed        | All required information is filled out and validated. Completed tasks must stay available for users to edit before they submit the final form.                                                                  |
| blocked | Cannot start yet | The task is locked until earlier tasks are finished. This is most often used for the final "Review and submit" step.                                                                                            |

## Content & Accessibility Guidelines

#### Formatting Titles and Labels

- **Action-oriented titles (suggested):** Keep text short and unique. Start each title with an action verb to make it clear what these links are for, such as “Enter your employer address,” not just “Employer address.”
- **Change titles based on status (suggested)**: Update the title text based on the status. For example, before the person completes the task it might say "Enter your employer address". After the person completes the task, it could say “Edit your employer address”.

#### Status & Focus Management

- **Don't rely on color alone:** Use text labels and/or icons with accessible names to convey status changes.
- **Text progress over bars:** Do not use linear progress bars or steppers. This component is for non-linear flows, but a linear progress bar implies a linear flow. Instead, use descriptive text, such as "1 out of 3 tasks completed," or “2 out of 3 tasks remaining.”
